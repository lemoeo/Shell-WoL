# Mac 屏幕共享唤醒

在设备编辑界面选择唤醒方式：

| 方式 | 行为 | 必填配置 |
| --- | --- | --- |
| WoL 魔术包 (`wol`) | 保留发送魔术包的行为 | MAC、广播目标、UDP 端口、次数 |
| Mac 屏幕共享（VNC）(`mac_vnc`) | DH(30) 用户名密码认证成功后断开 | 目标 IP、VNC 端口、Mac 用户名、密码 |
| WoL＋Mac 屏幕共享（VNC）(`wol_mac_vnc`) | 先发送魔术包，再进行 VNC 认证 | 两组配置 |

旧设备没有 `wake_method` 时默认使用 WoL，无需手动迁移。纯 Mac VNC 不要求 MAC 或广播配置。VNC 端口默认 5900。目标 IP 建议在路由器中保留 DHCP 地址；Mac 需开启屏幕共享，且账户有访问权限。验证结果来自用户的 M 系列 Mac、macOS 27：认证成功后立即断开即可亮屏；其他机型和系统仍需实测。

## 认证后保持连接

`hold_seconds` 默认为 0，可设置 0–30 的整数秒。从认证成功开始计时；保持期间不发送 `ClientInit`、画面、键鼠或剪贴板请求。服务器提前断开会报告失败，不自动重新认证。

连接和认证（组合模式含 WoL 与网络等待）共用最多 30 秒预算。认证成功后允许额外保持配置时间，整个任务最多 30＋保持秒数。组合模式仅在 TCP 连接尚未成功时允许重试，连接成功后的协议失败、响应丢失或错误密码均不会触发第二次认证。WoL 发送失败仍尝试 VNC；两步分别报告，单步成功时显示部分完成。

## 配置与密码

`devices.yaml` 的公开字段示例：

```yaml
devices:
  - id: mac-mini
    name: Mac mini
    wake_method: mac_vnc
    ip: 192.168.1.100
    vnc:
      port: 5900
      username: yourname
      hold_seconds: 0
    probe_port: 0
    note: 客厅电脑
```

Mac 密码通过 Web 配置，不能填入这份文件。密码存放于 `--data-dir` 指定目录的 `credentials.yaml`，使用 AES-GCM 加密；随机密钥独立保存在同目录的 `credentials.key`。默认 `--data-dir ./data` 相对于工作目录。Linux 安装通常为 `/opt/shell-wol/data`，小米兼容固件为 `/data/shell-wol/data`，OpenWrt 为 `/etc/shell-wol/data`，macOS 用户安装为 `~/Library/Application Support/Shell-WoL/data`。

Unix 新建凭据文件权限为 0600；Windows 使用保护的文件 ACL，允许当前服务/进程账户、SYSTEM 和管理员访问。应由实际运行 Shell-WoL 的账户配置和使用凭据。备份和恢复时必须将密文与对应密钥一起保护，并保持文件权限。密钥与密文同在本机不能防御整个数据目录或主机失陷；不可把整个数据目录作为公开附件。

前端密码行为：

- 编辑时密码框始终为空，只显示是否已配置，不回填旧值，也不提供查看接口。
- 留空保留旧密码；输入新值替换；“清除已保存密码”明确删除，清除后需重新设置才能 VNC 唤醒。
- 修改目标 IP、VNC 端口或用户名时，需重新设置密码或明确清除旧凭据；凭据绑定设备及目标账户，不能静默转发给其他目标。
- 删除设备会删除对应凭据。切回 WoL 时保留未改变的 VNC 配置与凭据，方便切换回来；可在 VNC 模式下明确清除。
- 接口、任务、历史、日志和设备导出不包含密码、密文或密钥。设备导出只包括已支持的公开字段；原设备文件保存时继续保留 YAML 注释。
- 凭据和设备分别原子保存；普通写入失败会回滚，崩溃窗口内若配置不匹配则拒绝解密，不把密码发送给旧目标。

Mac VNC 认证需要后端恢复密码来计算协议响应，因此使用可解密加密，不能只保存 bcrypt 哈希。密钥缺失时不会自动覆盖现有密文，应恢复对应密钥。若无法恢复，需要清除旧凭据后重新配置；损坏密钥需在确认所有旧凭据不再需要后人工处理。

仅在可信网络使用 Apple DH 认证，它不提供带证书的服务器身份校验。现有 HTTP 管理页会明文传输当次输入的新密码；请优先通过本机或 HTTPS 页面配置。应用不在浏览器存储中缓存密码，但浏览器自身的密码管理器行为不由应用控制。

## 后台任务与结果

Mac 唤醒创建后台任务，前端用短请求查询进度，单次请求仍为 10 秒超时。刷新页面可恢复进行中任务；丢失查询连接后再次点击会查询已知任务，不自动重新发送认证请求。Web 服务进程内每设备同时一个任务，最多两个 Mac 任务，不设置无限等待队列。完成记录最多保留 256 条、10 分钟；持久历史仍遵守 `log_limit`。

任务执行中不能修改或删除对应设备。任务不依赖原 HTTP 连接存活；服务退出会取消任务并关闭连接。重复点击返回同一进行中任务；已完成后再次主动点击会发起一次新的操作。

任务状态分为运行中、完成、部分完成和失败。成功消息表示认证和指定保持步骤已完成，不表示服务端已经测量到物理屏幕点亮。TCP“检测”仍只检查端口，不执行 VNC 认证。

Web API 继续要求登录，写操作要求 CSRF：

- 保存设备的 JSON 可包含只写字段 `vnc_password` 和 `clear_vnc_password`；留空表示保留，清除与设置不能同时提交。
- `GET /api/devices` 只返回 `password_configured` 状态；运行中的设备含 `active_job_id`。
- Mac 模式 `POST /api/devices/{id}/wake` 返回 202 与 `job_id`；WoL 保留同步返回。
- `GET /api/wake-jobs/{id}` 查询任务进度和分步结果，仍要求登录。

## CLI、升级与卸载

按保存的设备方式执行，可与 Web 服务共存，无需再开写锁：

```sh
./shell-wol wake --data-dir /opt/shell-wol/data --device mac-mini
```

CLI 从加密存储读取密码，输出阶段和结果，不改持久历史。Mac 模式不接受 WoL 命令行覆盖参数，请编辑设备配置；直接 `wake --mac ...` 仍只发送魔术包。

升级保留凭据文件，默认卸载保留数据；`uninstall.sh --purge` 的校验、预览及删除清单包含 `credentials.yaml` 和 `credentials.key`。未知文件仍保留。

独立的 [mac-vnc-probe 验证工具](mac-vnc-probe.md)、构建脚本及测试完整保留。生产功能调用同一协议模块，固定使用 `auth` 阶段和设备的保持时长，不启动外部验证程序。

回退到不支持 Mac 模式的旧版本程序时，应同时恢复对应版本的设备配置备份；旧版本可能无法读取没有 MAC 的纯 VNC 设备。不要为回退而删除唯一的凭据密钥备份。
