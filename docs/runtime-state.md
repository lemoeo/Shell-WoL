# 数据文件锁与初始化令牌

新版 Go 程序支持这些功能；仅更新安装脚本不能让旧版二进制获得它们。需要重新编译或安装包含这些改动的新程序 Release。

## 数据文件锁

同一数据目录只允许一个写进程。Linux、OpenWrt 和 macOS 使用 `flock`，Windows 使用 `LockFileEx`，均由 Go 调用系统接口，无需在路由器安装额外的 flock 命令。

`data/.lock` 现在是普通文件，启动时申请非阻塞独占锁，保持到服务或初始化操作结束。正常退出、强制结束、设备重启后，系统释放锁；文件长期保留，文件存在不代表数据正在使用。不要手动删除运行中的锁文件，否则可能让其他进程锁定另一个文件。

`check`、`wake` 和 `token` 不作为数据写入者持有服务锁。菜单及自启动脚本通过 Go 程序检查锁状态；安装器的初始化命令在写 YAML 时持锁。POSIX 卸载器让 Go 持锁执行同步清理阶段，在所有数据写入结束后移除本安装的锁文件，避免与服务并发修改数据。

维护命令示例：

```sh
shell-wol lock --data-dir /path/to/data
# POSIX：持锁执行维护命令，子命令结束后释放；不要启动后台写入任务
shell-wol lock --data-dir /path/to/data -- sh maintenance.sh
```

Windows 的 `lock` 命令仅支持锁检查，常规服务、初始化和令牌功能均支持 Windows。安装事务使用的 `.install-lock` 与本节的数据锁不同；异常中断的安装事务仍需确认状态后恢复。

## 旧目录锁迁移

旧版本使用 `data/.lock/` 空目录。它没有记录持有者，因此新版不会擅自删除。升级前先停止旧服务，并确认没有任何进程使用同一数据目录。

小米路由器示例：

```sh
/etc/init.d/shell-wol stop
pidof shell-wol
```

确认无运行进程，包括其他路径启动的实例后，如果旧空目录仍存在，再执行一次：

```sh
rmdir /data/shell-wol/data/.lock
```

`rmdir` 只删除空目录。新版本的 `.lock` 是文件，不要用 `rm` 将它当作遗留锁清理。新锁格式也会阻止旧版程序误用同一数据目录；降级需先停服并按旧版本的迁移流程处理。

## 本地查看初始化令牌

```sh
swol token
# 小米路由器也可以直接使用：
/data/shell-wol/bin/shell-wol token --data-dir /data/shell-wol/data
```

菜单新增“查看初始化令牌”。使用运行账户或管理员账户；Windows 使用对应 exe 的 `token` 命令。

尚未初始化的 Web 服务在成功绑定监听端口后，将本次启动实际使用的令牌保存到 `data/.setup-token`。文件包含实例标识和令牌，Linux/macOS 权限为 0600，Windows 仅允许运行账户、系统及管理员访问；令牌内容写入临时文件前即设置这些权限，再通过重命名发布。

查看命令核对内核锁及本次实例标识，不生成新令牌。普通状态输出、Web 接口、配置和设备导出不包含令牌。

- 设置管理员密码成功后清理文件，再次查看提示“管理员已初始化，请使用密码登录”。
- 正常退出或启动失败时清理；端口绑定失败不会发布令牌。
- 强制退出可能留下私有文件，但没有活跃服务锁时不会显示其中的令牌。下次启动清理旧文件、生成新令牌；旧令牌失效。
- 卸载时清理令牌文件，默认保留的 YAML 与凭据不受影响。

procd 仍直接守护 Go 程序，无需增加日志包装脚本或依赖 `logread`。前台启动时仍会在终端打印初始化令牌。该文件只在未初始化启动时写入一次，不持续追加日志。
